# Phase 10 — Deployment system · **64 %** (authored, unexecuted against a live cluster)

**Delivered:** multi-stage, non-root Dockerfiles for API/worker and web (Next.js standalone) · `docker-compose.yml` (Postgres, Redis, Qdrant, API, worker, web, health-checked) · Kubernetes manifests via kustomize: API Deployment (rolling, probes, resources, read-only root FS, dropped capabilities) + HPA + PDB, dedicated **worker** Deployment, web Deployment, **a database migration Job** (`25-migrate-job.yaml`), in-cluster Postgres/Redis/Qdrant for dev/staging, Ingress with TLS and websocket timeouts, NetworkPolicy restricting data stores to API/worker · GitHub Actions: backend (Py 3.12/3.13), web, mobile, manifest validation, image build & push to GHCR, gated deploy that runs migrations to completion before rolling out · Prometheus-format `/metrics`, `/healthz`, `/readyz` · a documented staging-vs-production split · [deployment guide](../deployment.md).

**Verified:** every YAML file parses (including the new migration Job); every workload declares resource requests. A real `uvicorn` process was exercised over HTTP (health, readiness, CORS preflight, auth enforcement, three-language chat). The migration DDL the Job would run is verified to compile for PostgreSQL via Alembic's offline SQL emission (`tests/test_migrations.py`), and Redis resilience the multi-replica topology depends on is verified against a real in-process RESP-protocol implementation (`tests/test_redis_compat.py`) — both new this pass.

**Not verified — treat as a first draft:** no image has been built, no compose stack started, no manifest applied, no CI run, no migration Job actually executed against a live database. Docker and Kubernetes were not available in this environment. Likely first-contact issues: image tags/owner placeholders (`ghcr.io/OWNER/…`), `web/package-lock.json` must be committed for `npm ci`, ingress annotations assume ingress-nginx + cert-manager, and PostgreSQL has never actually run this code (asyncpg + the generated DDL are compile-verified, not execution-verified).

**Known operational gaps:** ~~no schema migrations (Alembic)~~ **resolved — see [phase-03's addendum](phase-03-backend.md#addendum--production-completion-mode-audit)**, though never run against a live server · ~~no Redis integration test~~ **resolved at the protocol level — see the same addendum** · no secrets manager wiring (manual `kubectl create secret`) · no log aggregation/tracing config (a per-request access log line was added this pass — still plain text, not shipped to any aggregator) · Prometheus alert rules and dashboards not provided · no backup CronJobs.
